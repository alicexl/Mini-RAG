## 和传统检索比：稀疏 vs 稠密

如果你接触过搜索引擎，可能听说过 TF-IDF、BM25、倒排索引。它们和 Embedding 解决的是同一个问题——**把文本变成可以数学计算的表示，然后衡量相似度**。但路线完全不同。

**传统路线：稀疏表示（TF-IDF / BM25）**

TF-IDF 的思路很直接：**一个词在一篇文章里出现越多、在所有文章里出现越少，这个词就越重要。**

比如"营收"在这篇文档里出现了 5 次，在其他文档里很少出现 → "营收"是这篇文章的关键词。把所有关键词的重要性数值排成一排，就得到了一个向量——**稀疏向量**。

为什么叫"稀疏"？因为词表可能有几万个词，但一篇文档只涉及其中几十个。向量里绝大多数位置是 0，只有出现过的词才有值。

```
词表:  [营收, 利润, 碳酸锂, 天气, 足球, ...]
文档1: [3.2,  2.1,   0,     0,    0,   ...]   ← 数值为该词的 TF-IDF 权重（示意）；只在"营收""利润"上有值
文档2: [0,    0,     2.8,   0,    0,   ...]   ← 只在"碳酸锂"上有值
```

**那查询时怎么打分？** TF-IDF 的相关性分数 = **TF × IDF**，两部分相乘：

- **TF（词频）**：查询词在这篇文档里出现得越多，越相关——"营收"出现 5 次的文档，比出现 1 次的更可能在讲营收
- **IDF（逆文档频率）**：一个词在越多文档里出现，区分度越低、权重越小——"的""是"几乎每篇都有，权重接近 0；"碳酸锂"只出现在少数文档里，权重很高

一篇文档对查询的得分，就是把查询里每个词的 TF×IDF 加起来——本质是"查询词在这篇文档里的加权命中次数"。BM25 是 TF-IDF 的升级版（词频做了饱和、再按文档长度归一化），打分思路一脉相承。

**倒排索引**就是这个稀疏向量的索引结构——记录"营收"这个词出现在哪些文档里，查询时直接反查，速度极快。

**Embedding 路线：稠密表示**

Embedding 的向量完全不同——**每个位置都有值，没有 0**：

```
（不再有词表的概念，只有 1024 个抽象维度）
文档1: [0.023, -0.157, 0.891, -0.015, ...]   ← 1024 个浮点数，每个都有值
文档2: [0.041, 0.083, -0.234, 0.067, ...]    ← 同样 1024 维
```

没有一个维度对应"营收"或"利润"——它们被编码在所有维度的组合里。

> **为什么几乎没有 0？** 可以把 1024 维想成 **1024 个"颜色通道"**——但和 RGB 三个通道不同，没有任何一个通道能单独解释含义，必须 1024 个一起看。训练时梯度下降会**反复微调整个向量**（每一维都在小幅变动），目标是把向量挪到空间中正确的位置，而不是像开关那样"打开"某几个维度、关掉其余的。关键在于：如果某一维长期停留在 0，就等于它没参与表达、白白浪费了一个维度——神经网络会倾向于**充分利用每一维**，所以最终几乎所有维度都是非零的小数，得到的就是稠密向量。

**核心区别**

|  | 稀疏表示（TF-IDF / BM25） | 稠密表示（Embedding） |
|---|---|---|
| **向量形式** | 每个维度=一个词，大部分是 0 | 1024 个抽象维度，每个都有值 |
| **怎么判断相关** | 查询词命中，按 TF-IDF/BM25 打分 | 查询向量与文档向量的余弦相似度 |
| **"营收"和"营业收入"** | 不同词 → 不同维度 → 无法关联 | 语义相近 → 向量相近 → 自然关联 |
| **索引结构** | 倒排索引（O(1) 查词） | 向量索引（遍历比对，大规模可用 ANN 加速） |
| **优势** | 精确匹配快、可控、可解释 | 理解语义、跨语言、容错 |
| **劣势** | 只能匹配字面、无法泛化 | 计算成本高、不可解释 |

一句话：**稀疏表示是"字面指纹"，稠密表示是"语义指纹"。**

它们不是谁替代谁的关系——生产级 RAG 通常两者都用（混合检索），各取所长。
